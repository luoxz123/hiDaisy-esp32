# Daisy 新欢迎语未播放：WAV 区块偏移兼容问题

## 现象

烧录包含 `daisy_intro.wav` 的固件后，唤醒成功，但没有播放新欢迎语。串口日志显示：

```text
E (...) audio: Invalid Daisy greeting WAV (75644 bytes)
I (...) audio: Prompt start played (10240 PCM bytes)
```

## 排查过程

- 日志中的 75644 字节与新 `daisy_intro.wav` 完全一致，证明新资源已经嵌入并烧录，不是旧固件问题。
- 新文件使用标准 16 字节 `fmt ` 区块，`data` 标识位于文件偏移 36。
- 旧文件使用 18 字节 `fmt ` 区块，`data` 标识位于偏移 38。
- 原实现写死检查 `wav + 38`，并写死从偏移 46 开始读取 PCM，因而拒绝合法的新 WAV。

## 根因

WAV 是 RIFF 区块格式，`fmt ` 区块长度以及 `data` 区块位置并非固定。播放代码错误地依赖旧文件的特定头布局。

## 解决方案

- 从 RIFF 头之后遍历所有区块，按区块声明长度和偶数字节填充寻找 `fmt ` 与 `data`。
- 校验音频为 PCM、16 kHz、单声道、16-bit。
- 使用实际 `data` 区块起点和长度播放，不再依赖固定偏移。
- 不支持的格式仍回退到原提示音，并输出明确错误日志。

## 验证

- 增量构建和链接成功。
- 新固件 `build/hilily-esp32.bin` 大小 `0x227920`，应用分区剩余 28%。

## 教训

解析 RIFF/WAV 资源必须按区块结构处理，不能假设所有编码器都生成 44 或 46 字节的固定文件头。资源大小与日志一致时，应优先判断为解析兼容问题，而不是烧录失败。
