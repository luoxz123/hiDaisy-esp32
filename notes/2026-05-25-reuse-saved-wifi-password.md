# 2026-05-25 Reuse saved Wi-Fi password

## 现象

配网页选择已经保存过的 Wi-Fi SSID 时，如果用户没有重新输入密码，旧实现会把该 SSID 的保存密码覆盖为空，导致后续连接失败。

## 排查过程

- 检查 `WifiManager::AddNetwork()`，发现同名 SSID 会先删除旧记录，再用表单提交的 `pass` 保存。
- 检查配网页，已保存网络只提供删除按钮，没有直接使用已保存密码连接的入口。
- 检查 `/save` POST 处理，密码字段允许为空，因此需要在保存逻辑里区分“开放网络”和“复用旧密码”。

## 根因

重复保存同一 SSID 时没有保留旧密码；空密码被当作新密码写回 NVS。

## 解决方案

- `AddNetwork()` 对已有 SSID 且提交密码为空时，复用原记录中的密码。
- 已保存网络列表新增 `Use` 按钮，提交该 SSID 且不提交密码，从而直接使用保存密码。
- `Add / Update Network` 表单提示：已保存 SSID 的密码可留空，只有需要更新密码时才输入新密码。
- 保存网络列表中的 SSID 做 HTML 转义，避免特殊字符破坏隐藏表单值。

## 教训

配置页的“空密码”语义必须结合上下文处理：新 SSID 空密码表示开放网络；已有 SSID 空密码应优先表示复用保存凭据，避免误清除可用密码。
