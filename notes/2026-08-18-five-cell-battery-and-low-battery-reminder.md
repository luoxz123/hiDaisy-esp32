# 五格电池显示与低电量语音提醒

## 现象

设备屏幕没有稳定显示剩余电量，电量低时也没有周期性充电提醒。

## 排查过程

- 电池 ADC 已在启动时初始化，并每 5 秒更新一次滤波后的电压。
- 应用层原本每 10 秒把百分比传给 UI，因此采样链路已经存在。
- 原 UI 在电量大于 90% 时主动隐藏电池条，是“没有显示”的直接原因。
- 原红色阈值为 `< 20`，恰好 20% 时不会显示红色。
- 当前协议没有低电量 TTS 请求类型。
- 尝试使用 Windows System.Speech 生成本地提醒音，但当前运行环境没有可用语音，因此没有嵌入不可验证的空音频文件。

## 根因

电池显示采用会隐藏的连续进度条，且低电量边界条件不符合产品要求；固件与服务器之间也缺少低电量提醒事件。

## 解决方案

- 将顶部电池条改为常驻的 5 个独立电池格，每 20% 对应一格。
- 电量为 1%～20% 时亮一格；20% 及以下使用红色，其余亮格使用绿色。
- 应用每 10 秒检查电量，首次进入 `<=20%` 立即排队提醒，之后成功上报间隔至少 5 分钟。
- 仅在设备处于 Idle、扬声器未播放且 MQTT 在线时发送，避免打断对话或与 TTS 争用 I2S。
- 上报 `low_battery`，包含百分比、电压和固定英文文本；同时本地显示 15 秒低电量文字覆盖层。
- 在 API 文档中定义服务端应跳过 ASR/LLM，直接合成 TTS，并按设备做 5 分钟幂等限流。

## 服务端事件

```json
{
  "type": "low_battery",
  "battery": 20,
  "voltage_mv": 3400,
  "text": "Low battery, please charge as soon as possible."
}
```

## 验证

- ESP-IDF 增量构建、链接和分区检查成功。
- 固件 `build/hilily-esp32.bin` 大小为 `0x239d10`（2333968 字节）。
- 应用分区剩余 `0xc62f0`（26%）。
- 当前环境缺少 `gh` 命令，未能直接修改私有服务端仓库；服务端仍需按 `docs/API_SPECIFICATION.md` 增加事件处理。

## 教训

- UI 不应根据“可能正在充电”的推测隐藏满电图标，应始终显示真实电量状态。
- 周期提醒必须同时在终端和服务器限流，避免重连或重复事件造成连续播报。
- 音频提醒应避开播放和对话状态，不能让周期任务直接争用 I2S。
